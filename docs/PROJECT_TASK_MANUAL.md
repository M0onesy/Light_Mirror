# 明镜 MingJing 计划书打磨与开发任务手册

> 内部协作版 · 2026年10月阶段整理。当前工程为 `mainProj/mingjing-next`。本手册与 `mainProj/明镜_计划书打磨与开发任务手册.md` 保持同一版本；评委提交主体使用 `明镜MingJing_项目计划书.docx` 导出的PDF。前五部分写目标、实现和验收方法，尾部问题附录用于内部开发，不作为初赛计划书正文。

## 1. 计划书打磨：向评委证明我们要做什么、为什么能做成

### 1.1 一句话定位与产品目标

明镜是面向A股历史财务事实的原生金融Agent：以研究报告纠错为主线，提供同一材料下的财报分析、追问、补证与重查；模型负责理解和自主工具调用，明镜内核负责事实、计算和判定。

普通用户只双击 `MingJing.exe`，在复用并改造的Harness Web界面中选择材料、配置API、启动任务、查看证据和导出报告。用户无需安装Python、Node或pnpm；大型财报语料保持外部路径，密钥由当前Windows用户的DPAPI保护。模型可选择DeepSeek、Kimi、OpenAI GPT或受支持的自定义协议，不与一家API绑定。

核心价值应写成三个可检验的承诺：

1. **数字有出处。** 每项判定关联原文位置、来源报告、页码坐标、披露单位与精度、公式和实际操作数。
2. **判断有边界。** 截止日、披露版本、会计口径、来源方法和公式前提共同约束结论，模型不能提交金额真值、自由公式或判定。
3. **全过程能复查。** 全文提及账本保留全部原文出现位置，运行锁和审计贯通材料、模型、工具与结果，支持内核和原生Agent两层离线重放。

“独立Agent”是独立的金融业务系统、工具、状态与数据资产，不是自训练基础模型；原生Harness的模型—工具—观察循环必须实际发生，不能用一组prompt或固定API调用流水线代替。

### 1.3 写作与材料纪律

正文使用“拟实现/设计为/目标为/验收将采用”等计划语态。已具备的能力用架构和可执行方法说明；实测数字必须注明样本边界、版本、来源收据及分母。局部11条结果、生成机制集或单页演示均不能证明全文质量，不进入摘要成绩承诺。

不得把“覆盖率100%”单独用于宣传。必须分开处理完成率、有效判定覆盖率、金融提及召回和三态占比；原文重复位置与去重断言分别报告。任何目标数字要显式写“验收目标”，文献成绩不得当作本项目成绩。

保留Word原有14章、图表、参考文献和附录，逐项核对E1–E9、X1–X6、A1–A5、架构和命令。图中通用L0/L1/L2仍可作为概念图，但图注要说明Python宿主、原生循环、受控RPC和当前目录；不得留下“系统无对话”“只用DeepSeek”“CLI为唯一产品”等旧表述。目录、交叉引用、页码由Word更新后导出PDF，再逐页确认表格跨页、图像、公式和中文字体。

团队信息、指导教师、机构名等由实际参赛成员填写，不由Agent编造。初赛视频与PDF最终规格以官方竞赛通知为准；视频重点展示一条多步核查链、原PDF证据与可执行修改，另展示断网重放作为可靠性说明。

## 2. 当前工程约定与实现路线

### 2.1 唯一工作根与目录

在 `mainProj/mingjing-next` 开发、运行和构建；旧 `mainProj/mingjing` 仅作历史基线，不能通过PYTHONPATH加载其模块。源码入口为 `python -m mingjing.launcher`；官方模块来源断言须通过后才构建。旧工程的真实`.git`可能为当前worktree的common-dir，清理时必须保护。

| 目录 | 作用 | 交付方式 |
| --- | --- | --- |
| `mingjing/`、`kernel/` | 宿主、Agent、确定性内核、协议和生命周期 | GitHub与核心审阅包 |
| `runtime/finance-plugin/` | 金融Cordis插件、RPC、角色与profile | GitHub与核心审阅包 |
| `runtime/harness/` | 源快照、协议、依赖和资源锁 | 保留锁，供可重建检查 |
| `vendor/harness/` | 锁定上游源码及许可 | GitHub完整源码，不带node_modules |
| `runtime/finance-carrier/` | 独立Node金融运行时闭包 | 完整开发拷贝/EXE，不放核心审阅包 |
| `frontend/`、`web/` | Harness UI源与静态资源 | 来源收据绑定后交付 |
| `rulepack/` | 规则、口径、准则快照与版本锁 | 所有代码交付形态 |
| `bench/`、`tests/` | 样本、金标工具、实验与回归 | 小型可再分发部分公开 |
| `samples/` | 虚构离线演示 | EXE内嵌与核心审阅包 |
| `runs/` | 成功/失败、会话、补证、旧锁和重放证据 | 本地保护，按冻结闭包选择性导出 |
| `scripts/`、`docs/` | 建库、验证、构建、说明与合规 | 与对应源码版本一起发布 |

上游来源默认统一为 `vendor/harness`；显式外部`--upstream`路径只有完整快照哈希匹配才可使用。原生循环不重写，源码快照0.1.6-alpha.2没有可信git_commit时记录null，不制造commit。运行时指纹要覆盖实际JS、包映射、插件和原生依赖，不仅Node/bootstrap。

### 2.2 材料、事实与口径

默认财报主根 `mainProj/年报和半年报/reports`，会计知识库唯一主根 `mainProj/存放会计准则`；Web可选择外部目录。原始大语料不进EXE/Git，草稿复制到任务工作区并计算SHA-256。采集覆盖定期报告、招股书、首/二轮问询回复、审计附注、更正公告和必要历史报告；官方记录优先，稳定发行人身份关联新旧代码。

当前并行科技已曝光研报的回溯截止日为 **2024-04-22**。此日期只是该案例输入，不强制所有新任务同日期。公告未知或截止日之后的材料不作为当时已知依据；检索、读块、引用、补证和局部重解析使用同一时序守卫。

来源事实保留科目、有效期间、会计口径、披露版本、币种、业务/产品/客户、方法ID和原表身份。查询先区分found/missing/conflict/low_confidence/date_unknown/source_ambiguous；只有明确missing且操作数完整时可派生，不得以重算绕过X4。

同表口径继承必须有“归母权益＋少数股东权益”或“归母利润＋少数股东损益”等结构证明，并受表实体边界约束。明确引用的业务来源表可做转述核查，未知会计口径仍保留；不能因同页或金额相近强填合并。法定“其他流动负债”与券商残项独立，方法和组成必须来源支持。

### 2.3 数字与规则契约

所有金额、比例、区间和公式运算使用Decimal或登记的Decimal区间算法。来源与陈述分别保留单位和小数位；粗来源与细陈述只能展示“披露精度下相容”。模糊约/左右默认h=2%，工作点扫描0.5%/1%/2%/5%；严格超过/不足是开闭阈值集合，不能当点值或套h。

错误分类固定为E1数值、E2期间、E3口径、E4单位、E5计算、E6引用、E7逻辑比较、E8材料不可验证、E9披露版本错配。E8为未知状态并附X码，不等同“财务有错”。X1缺可用事实、X2公式/前提、X3绑定/方法/口径、X4解析置信/冲突、X5缺回溯日期、X6提及维度/结构。A1合法旧版引用、A2模糊限定、A3用语、A4内部不一致、A5财报复核信号与三态分列。

每张规则包含ID、版本、适用范围、依据引文、公式AST、量纲、前提、排除、正例、反例、边界例及专业签发。`MetricSpec`贯通识别、枚举、工具依赖、公式和分析目录；不得存在“公式已写但Agent不能调用”的双份注册。

扣非四输入：`NP_PARENT-(NRI_TOTAL-NRI_TAX_EFFECT-NRI_MINORITY)`，缺项不默认为零。已披露归母税后非经常净额使用独立卡。负/零基数同比、ROE、摊薄EPS、现金流桥接与其他来源方法均按实际定义授权，金额相容不得反推定义。

### 2.4 原生Agent、工具与配置

流程为：锁定材料与配置→全文分区/提及建账→A/B独立绑定→一致闸→事实与规则查询→有界追检/局部重解析→内核核查/分析→槽位报告复扫→冻结归档。planner与verifier独立，reporter只读已冻结结果，可信协调器管理状态和预算。

模型只选登记资源ID、维度、方法和语义枚举，不能写金额真值、公式或判定；候选金额在绑定视图屏蔽。真实角色、会话和资源锁由插件注入，宿主再次校验，禁止模型伪造身份。四个标准MCP服务复用dispatcher；内部可信计算与冻结分析读取分别授权。

配置v2管理provider、协议、模型目录、密钥引用、能力与角色路由。普通连接和Agent工具往返测试分别显示；HTTP200不算Agent通过。不得自动替换用户已存模型或密钥；跨供应商备用须显式批准。生产profile默认禁用Shell、Code Mode、开放网络、任意文件工具、自修改、插件安装和遥测。模型API网络由批准适配器使用，DPAPI密钥通过私有凭据RPC批准解析，不用明文credentials-local。

现有默认核查预算为128模型请求、1000工具、100万Token、30分钟；追问为12请求、80工具、15万Token、3分钟。专项全文预算可用独立快照提高到512请求、4000工具、200万Token、60分钟，不覆盖用户保存配置。Token不是金融方法授权；超限、取消或缺一方提交保留pending/partial，未知用量和价格记unknown。

### 2.5 结果、恢复与重放

每个数字原文occurrence保留位置与处理状态；不得去重后删除正文出现。分别展示处理完成率、有效判定覆盖率、弃权率、待处理、范围外和规则排除，并按公司财务、行业、运营、预测、假设分层。所有报告、UI、导出和评分读取同一统计结构。

修改建议固定五项：正确值、来源/证据ID、计算式、规则/准则依据、直接替换文本。数字保留来源支持精度；reporter只能引用槽位，输出复扫拒绝自由数字与无依据结论。

恢复先验证材料、配置、规则、插件和运行时，再读取冻结草稿、预算、A/B与工具轨迹，最后原子发布检查点；失败时旧材料与状态字节不变。补证、追加材料和口径澄清共用新版本构造器，继承且重新验证有效补证，原结果只读。消息归档冻结输入、父任务、缓存、轨迹、引用与答案，引用限制在提交/归档一致。

kernel replay重新计算数字逐字段一致；agent replay用匹配缓存重新执行原生工具循环；消息replay关联父锁。三者均离线，缓存缺失或不匹配直接失败。历史锁不得改路径/指纹来冒充新代码可重放；源码快照保存实际旧字节及受保护资源引用。
