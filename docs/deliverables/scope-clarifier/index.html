    如何使用（合规说明）
    

      
这是什么

      

        明镜在核查研报数值时会先确认数据口径（合并报表 / 母公司报表）。若原文通篇未声明口径，
        明镜不会猜测，而是将这些条目列为「因口径弃权」并给出可澄清的分组。
        本页把这些分组呈现在你面前，由你显式选择口径。
      

      
为什么必须由人提供口径

      
    
        
  • 澄清创建的是一个新的条件核查任务，它从不「证明」原研报的口径。
    • 
        
  • 系统绝不默认猜测口径，符合项目红线：口径不明时不得默认为合并口径。
    • 
        
  • 生成的 provenance 会被记录在结果目录的 clarifications.json（全篇声明）
            或 scope_clarifications.json（分组澄清）中，并附 SHA-256 校验。
    • 
      

      
两种澄清方式

      
    
        
  • 全篇声明：所有分组选择同一口径时，使用 --scope-declaration 合并|母公司。
    • 
        
  • 分组澄清：分组口径不一致时，使用 --scope-clarifications-json，
            传入形如 [{"scope":"合并","selector":{"claim_ids":["claim-00001", ...]}}] 的 JSON 数组。
    • 
      

      
操作步骤

      
    
        
  • 逐组选择「合并」「母公司」或「保持弃权」。
    • 
        
  • 点击底部「生成重算命令」。
    • 
        
  • 复制命令到终端执行（在项目根目录、使用 py -3.12）。
    • 
        
  • 结果输出到 runs/full-scope，与 runs/full-off 对比弃权数量的变化。
    •
