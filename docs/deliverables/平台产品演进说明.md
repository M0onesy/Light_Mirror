# 明镜 MingJing 平台产品演进说明

> 对比基准：项目最初发布版 → 当前版本（含本轮最新改动）
> 面向读者：产品负责人与评审人
> 说明：本文只讲产品与功能层面的变化，不涉及实现细节。

---

## 一句话总览

明镜从最初发布时的一个**单页原生 Agent 高级工具**（面向懂技术的使用者、偏调试视角），演进为一套**面向投研人员的六页平台**：核查结果不再只给出"对/错"，还解释"为什么无法核实"；并补齐了**弃权诊断**与**口径澄清**两条闭环；双端界面统一为浅色专业风、可互相跳转；主界面只保留业务必需项，把工程自测内容移出。

---

## 演进主线

| 能力域 | 最初发布版 | 当前版本 |
| --- | --- | --- |
| 核查能力 | 只输出"已核实／有误／未能核实"三类结论 | 能对"未能核实"归类归因，区分缺材料与口径不明；口径来源可追溯；封堵拼凑式"假核实" |
| 诊断与澄清 | 弃权只是一个数字，无从下手 | 弃权诊断看板（看结构、逐条下钻）+ 口径澄清工具（逐组声明、生成重算），两条闭环打通 |
| 平台界面 | 单一高级界面，能力分散 | 六页统一平台（工作台／核查结果／知识库／任务历史／设置／说明），高级能力仍在高级界面 |
| 交互体验 | 小屏错位、按钮静默失败、录入不符习惯 | 小屏可用、操作有反馈、录入更顺手，界面按业务需要精简 |

---

## 一、核查能力：从"只报结论"到"能解释为什么没结论"

| 变化 | 最初发布版 | 当前版本 | 对使用者意味着什么 |
| --- | --- | --- | --- |
| **未能核实按原因归类** | "未能核实"是一个笼统的桶，看不出原因 | 按原因分类，明确区分**真缺材料**（补对应报告即可复核）与**口径不明**（需先声明用哪个口径） | 得到一张可执行清单：知道该补哪份材料、该澄清哪个口径，而不是笼统感觉"系统没查出来" |
| **口径澄清证据链** | 缺少"这个指标按什么口径算"的可追溯记录 | 口径来源完整留痕：由哪条原文线索得出、使用者声明了什么、重算依据是什么 | 结论可复核、可审计；口径不是系统暗自猜测 |
| **抗"一源多标"凑数校验** | 一段原文被挂到多个互不相干指标上凑数，难以识别 | 同一段原文最多支撑两个不同指标，超出即判为凑数、整组不予采用 | 避免"看着有依据、其实是拼凑"的假核实，结论更可信 |
| **口径出处审计** | 已有一套口径定义，但存在共用无关条款、默认写死等问题 | 逐项审计出处，只采信"原文明示"的口径，来源不成立的不作依据 | 守住"不得默认采用合并口径"这条底线 |

## 二、诊断与澄清：两条闭环

### 2.1 弃权率归因诊断看板

| 维度 | 内容 |
| --- | --- |
| 原来 | 弃权率高只是一个数字，看不出结构，无处下手 |
| 现在 | 把弃权按构成分解、按根因展开，可逐条下钻到"具体哪一条、什么原因"，并可跳转到口径澄清工具直接处理 |
| 意味着 | 从"知道弃权多"升级到"知道为什么多、先处理哪一类" |

### 2.2 报表口径澄清交互工具

| 维度 | 内容 |
| --- | --- |
| 原来 | 口径澄清依赖命令行或口头约定，容易误用、出错 |
| 现在 | 待澄清口径按组列出，逐组选定口径并生成重算命令；内置四层防误用（原文线索预选、系统建议提示、动态横幅、**必须勾选"已核对原文"才能提交的硬闸门**），生成的命令会注明口径来源 |
| 意味着 | 非技术使用者也能安全完成口径澄清；未确认就不会生成命令 |

## 三、平台界面

### 3.1 六页主平台成型

| 维度 | 内容 |
| --- | --- |
| 原来 | 能力分散在多个入口，缺少统一门户 |
| 现在 | 统一为六页：**工作台、核查结果、知识库、任务历史、设置、说明**；高级能力保留在"高级界面"，主界面聚焦日常核查 |
| 意味着 | 日常使用在一处即可完成全流程，减少入口切换 |

### 3.2 双端界面视觉统一与跨端跳转

| 维度 | 内容 |
| --- | --- |
| 原来 | 两个界面视觉风格不一致（一深一浅），来回切换体验割裂 |
| 现在 | 统一为浅色专业风，两个界面之间可**双向跳转** |
| 意味着 | 同一套产品观感，切换不再"跳戏" |

### 3.3 小屏适配与可键盘操作

| 维度 | 内容 |
| --- | --- |
| 原来 | 窄屏下导航被挤出视口、按钮行不换行、设置页下拉框撑破布局；键盘操作看不到焦点 |
| 现在 | 导航自动换行、按钮行可换行、下拉框不再溢出、键盘焦点清晰可见 |
| 意味着 | 笔记本分屏、小窗口以及只用键盘的场景都能正常使用 |

## 四、交互体验（本轮重点）

### 4.1 工作台提交区

| 变化 | 最初发布版 | 当前版本 | 对使用者意味着什么 |
| --- | --- | --- | --- |
| **说明文字排版** | 用间隔点把三件事串成一行，操作入口与说明混在一起 | 重新分行排版，操作入口与说明文字分层呈现 | 一眼分得清"能点什么"与"会发生什么" |
| **试用示例按钮** | 名为"一键演示（虚构样例，含预埋错误）"，更像免责声明 | 更名"**试用示例**"，说明文字移到悬停提示；点击后载入内置样例并直接跑到核查结果页 | 名称通俗、愿意尝试；一按就能看到完整效果 |
| **从知识库选择材料** | 异常时**完全静默**，使用者以为按钮坏了 | 服务未连接、知识库为空、没有勾选、成功加入四种情况都有明确提示 | 每一步都有反馈，不再靠猜 |
| **任务类型选择** | 选中后只有边框变化，容易误以为会切换界面 | 选中后，开始按钮旁的提示文字随之变化 | 清楚当前选的是"自动识别／研报核查／财报分析" |
| **可选项折叠面板** | 标题带括号说明 | 标题简化为"可选项" | 更清爽 |

### 4.2 结果页精简

| 变化 | 处理方式 | 功能是否还在 |
| --- | --- | --- |
| 重放验证按钮 | 从结果页撤下 | 在，高级界面本就具备，主界面不重复提供 |
| 材料会话与补证（整块） | 从结果页撤下 | 在，高级界面本就具备 |
| "推定与假设"页签 | 撤下页签 | 在，改为"全部陈述"页顶部一行说明 |
| "分级统计"页签 | 撤下页签 | 在，由原有多条件筛选承载 |

### 4.3 知识库精简

| 变化 | 最初发布版 | 当前版本 |
| --- | --- | --- |
| 顶部概览 | 五项，含"去重节省上传""任务引用次数""缓存条目"等工程指标 | 精简为两项：**文档、公司** |
| 留痕校验 | 名为"校验哈希链"，偏技术表述 | 更名"**校验留痕完整性**"，说明改为"谁在什么时候用过这份材料" |

### 4.4 设置页精简

| 变化 | 处理方式 |
| --- | --- |
| "测试 Agent 工具闭环" | 移出（属开发自测内容） |
| "高级界面"说明面板 | 删除（与顶部入口重复） |
| 保留项 | 模型配置、测试连接、发现模型、运行环境 |

### 4.5 研报日期输入方式改造

| 维度 | 内容 |
| --- | --- |
| 原来 | 使用系统原生日期控件，空值时显示中文"年／月／日"，不符合录入习惯 |
| 现在 | 可直接键入 `2026-10-15`；右侧保留日历按钮用于点选；手输 `2026/10/15`、`20261015` 等形式会自动归一化 |
| 意味着 | 录入更快、更符合习惯，格式自动纠正 |

### 4.6 新增本地服务启动方式

| 维度 | 内容 |
| --- | --- |
| 现在 | 仓库根目录新增一个**双击即可启动平台并自动打开浏览器**的启动脚本，不依赖任何构建步骤 |
| 解决的问题 | 此前的成品程序内置的是**旧界面**，要看到最新界面必须用这种方式启动 |
| 意味着 | 评审与演示可直接看到最新平台，无需任何构建操作 |

## 五、界面精简的取舍说明

主界面本轮做了"减法"。为免误读为功能被删，统一说明去向：

| 被撤下的内容 | 去向 | 是否仍可用 |
| --- | --- | --- |
| 重放验证（结果页） | 高级界面 | 是 |
| 材料会话与补证（结果页） | 高级界面 | 是 |
| 推定与假设（页签） | 合并进"全部陈述"页顶部一行说明 | 是 |
| 分级统计（页签） | 合并进原有筛选下拉 | 是 |
| 去重节省上传／任务引用次数／缓存条目 | 移除 | 属工程指标，非业务信息 |
| 测试 Agent 工具闭环 | 移除 | 属开发自测 |
| 高级界面说明面板 | 移除 | 顶部已可直接进入 |

## 六、保持不变的红线与边界

以下原则在全部演进过程中**始终未变**：

- **不默认采用合并口径**——口径不明时宁可弃权，也不暗自选择一个口径。
- **不把"未核实"改写成"已核实"**——判定结果一经产生不被改写。
- **口径不明时必须弃权**，不凭数值巧合倒推结论。
- **不臆造数值**——数值事实必须来自原文或确定性重算。
- **无模型时以纯确定性内核完整运行**，功能不因缺少模型而缺失。
