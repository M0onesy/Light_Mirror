# 补材料与分析展示的接口约定

`POST /api/sessions/{session_id}/materials` 接受已验证路径 `corpus`、`draft`、`facts`，以及可选 `scope_declaration`（空字符串、合并、母公司）。仅提交口径澄清也可以建立新任务版本。该接口拒绝候选金额、事实内容或判定。原草稿、原结果和原会话锁保持只读。

会话中的 `corpus` 表示**追加**财报文件或目录。新任务保持原 `corpus`，并在 `corpus_additions` 中保存追加材料。重复规范路径只登记一次，追加材料最多 32 项。所有路径沿用允许目录和符号链接限制。`draft` 表示替换草稿；未同时重新声明口径时清除旧声明，防止旧口径错误应用到新文档。

任务接口、历史、重查及 CLI 同样支持 `corpus_additions`。CLI 对应可重复的 `--corpus-addition` 参数。每份语料分别解析并在自己的根目录内解析事实来源；原语料无事实时使用的已登记备用索引会与追加语料并存。新运行清单锁定主材料和追加材料的报告、事实索引及语料索引；输入变化后重放拒绝通过。

公开结果视图中，`analysis.metrics[].display_value` 由 Decimal 展示层生成；金额使用元，每股收益使用元/股，比率和同比、环比显示百分比与标准小数。`analysis.signals[].display_text` 和 `analysis.events[].display_text` 提供中文复核说明、阈值、来源与证据。所有展示字段均为只读投影，不写回冻结的 `results.json`，也不改变事实、公式、判定或原核查计数。

补证产生新任务后应打开新结果；后续问题基于新任务创建材料会话，继续使用新的资源锁。旧会话仍引用原任务。开发回归不能代替独立金融金标、供应商真实调用及最终 Windows 发布验收。

## 原财报页面局部补证

在 Harness 证据面板打开已登记的原 PDF 页面后，可以点击“重新解析该页”。后端只接收原任务的 `report_id`、整数 `page` 和可选 `binding_id`，重新读取该页及相邻页，最多三页；不能提交文件路径、候选金额、自由公式或判定。人工页面补证可不绑定陈述；原生 Agent 的重解析工具仍须通过独立的绑定及缺证守卫。

`POST /api/runs/{id}/reparse` 将补证包保存到独立目录，`GET /api/runs/{id}/reparse-packets` 列出该冻结材料版本的包。`ready` 且有新增事实的包可以点击“创建补证版本”，向 `POST /api/runs/{id}/rerun` 提交 `reparse_packet_ids`（最多 12 个不重复 ID）。应用前重新核验父任务、所有材料、参数、包哈希及原 PDF 局部解析结果。`conflicts` 显示 X4 并要求专业核对；`no_new_information` 保留记录，但两者都不能应用。原任务的事实、结果、审计和清单不改写；新任务完整重查并单独生成重放记录。

已应用补证材料的新任务暂不支持直接普通“重新核查”，以免静默丢失补证事实。请回到原父任务选择补证包创建另一个版本。若公司、材料、期间、口径或回溯日期改变，应新建任务；旧包不会自动适用。此阶段不隐式继承多代补证包。

就绪包支持“预览新增事实”：`GET /api/runs/{id}/reparse-packets/{packet_id}` 重新执行可信包加载和原页重建后，向人工界面展示科目、公司、期间、合并／母公司、扣非口径、披露版本、单位、Decimal 数值和证据 ID。该详情不会进入模型的工具摘要。`GET /api/runs/{id}/reparse-packets/{packet_id}/evidence/{evidence_id}` 仅接受包内新增事实的证据，默认返回定位信息；`?format=png` 在内存渲染原 PDF 页面及高亮区域，不向父运行写入缓存。额外路径、页码、候选金额或未知格式均拒绝。

新版本的“补证材料”页列出所有新增事实，包括未被本次陈述或分析指标引用的事实，支持逐条打开原始证据。此页及证据面板明确标为“原页补证事实”；新增材料本身不等于研报已核实。

任务结果页的“可用页面补证”直接列出本任务的独立包，包括 Agent 自主局部追检导出的包。即使缺证陈述没有证据 ID，也可从这里预览及创建补证版本。无包时该区默认折叠；“刷新补证包”重新读取当前登记状态。此入口与原页证据面板共用预览和应用组件。
