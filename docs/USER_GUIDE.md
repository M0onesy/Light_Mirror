# 明镜金融 Agent 使用手册

本手册适用于当前源码与对应阶段候选程序。明镜用于上市公司历史金融事实核查、财报分析和材料追问；数字事实、计算与判定由 Decimal 确定性内核产生，原生 Harness Agent 负责语义绑定、检索、补证与报告组织。模型供应商可以选择 DeepSeek、Kimi、OpenAI GPT 或兼容服务。

## 1. 第一次使用：先完成离线演示

1. 在 Windows 11 x64 上把 `MingJing.exe` 放到普通可读目录，双击启动。正常使用无须安装 Python、Node 或 pnpm。首次启动会解包必要运行资源，原生运行时按哈希缓存到本地用户目录。
2. 默认浏览器打开本机页面，地址为 `http://127.0.0.1:<自动端口>`。这个地址只属于当前电脑；修改端口后需重新启动。重复双击会打开同一用户数据目录中的已有实例。
3. 点击「运行内置离线演示」。它使用内置虚构样例，默认不调用模型 API。看到原文、结果、公式、证据及运行记录后，再配置真实材料。
4. 演示完成后选择「内核重放」，核对离线重算是否通过。
5. 退出时使用页面中的「退出明镜」。关闭浏览器标签页不会停止后台服务。切换不同版本前先退出旧实例。

如果浏览器未自动打开，检查是否关闭了「启动时自动打开浏览器」，或是否已有旧实例。不要把其他程序的端口页面当成明镜页面。阶段包的版本、文件 SHA-256 和具体测试边界见同包构建回执。

## 2. 设置页的五个区域

页面右上角打开「设置」。每个区域有自己的保存按钮；检测使用已保存的配置，编辑后应先保存。配置使用 revision 防止多个页面互相覆盖；发生冲突时重新打开设置并合并修改。

| 区域 | 需要设置什么 | 通常何时使用 |
| --- | --- | --- |
| 模型与密钥 | 供应商、协议、API 地址、Token、模型、输出上限、超时和兼容参数 | 第一次启用 Agent，或更换模型 |
| 角色与预算 | 默认模型、A/B/report角色路由、任务与追问预算 | 调整成本、耗时或使用不同角色模型 |
| 数据与路径 | 草稿、财报、知识库、事实索引、输出、临时目录 | 接入真实材料及指定结果位置 |
| 运行时 | 内嵌金融 Harness 或开发用外部运行时、启动超时 | 检查原生 Agent 能力 |
| 服务与安全 | 本地端口、访问 Token、允许根、日志目录、配置导入导出 | 更换目录、加强本机访问控制或排障 |

新设置只影响后续任务。当前任务继续使用启动时冻结的配置、角色路由、材料和预算；材料追问也使用所关联任务的快照。需要使用新配置时点击「按当前设置重新核查」，建立新任务。

## 3. 配置模型/API

### 3.1 添加供应商

在「模型与密钥」选择添加供应商预设，填写供应商 ID、显示名称、实际 API 地址、API Token 和模型 ID。模型名称必须使用账号实际可调用的标识；不要直接套用别人的模型名称。

| 服务 | 推荐选择的实际协议 | 地址示例与注意事项 |
| --- | --- | --- |
| DeepSeek 官方 | DeepSeek 原生适配 | `https://api.deepseek.com`；预设负责相应路由，模型由账号查询或自行填写 |
| Kimi / Moonshot | OpenAI Chat Completions 兼容 | 使用 Moonshot 官方当前区域地址，例如 `https://api.moonshot.cn/v1`；模型以账号目录为准 |
| OpenAI GPT | OpenAI Responses，或服务确实支持的 Chat Completions | `https://api.openai.com/v1`；选用实际支持工具调用的模型 |
| 自定义网关 | Chat Completions、Responses 或 Anthropic Messages 中其实际支持的一种 | 填写网关规定的 API 前缀，避免重复 `/v1` 或重复请求路径 |

点击「保存供应商与密钥」。Token 输入框留空表示保留当前加密密钥，不表示删除。Windows 使用当前用户 DPAPI 保存密钥；明文不会进入普通配置导出。换电脑或换 Windows 用户后必须重新填写 Token。

可点击「发现模型」查看服务公布的模型目录，选中后点击「使用所选模型」，再保存。部分服务没有模型目录接口，此时可以手动填写。发现模型失败不必然表示聊天接口不可用。

### 3.2 两种测试都要理解

「连接测试」检查已保存连接和有效响应。「Agent 工具闭环测试」还会让模型调用只读工具、获得工具结果并继续作答。普通 HTTP 200、模型列表或一句正常回复不能证明 Agent 工具能力。

检测结果应区分已声明、实际运行、实测通过、不支持和未知。一个模型检测通过，不等于整个供应商所有模型都通过。无相应凭据时，Kimi/GPT 的真实调用状态为 `not_executed`，不会因适配代码或模拟测试而变为通过。

默认不会在故障时静默切换到另一家公司 API。原生链路故障会明确显示原因并降级到纯内核；材料只发送给本次任务已批准的供应商。检查「允许向此供应商发送当前任务材料」后，才对该供应商开放材料访问。

### 3.3 输出、思考与超时

「单次输出 Token 上限」约束每次回复，不等于整个任务预算。频繁截断时先查看停止原因，再增加输出上限。思考模式按实际适配器处理；不要把 DeepSeek 参数复制给所有供应商。

请求超时控制单次 API 请求；运行时启动超时控制 Harness 握手；任务总时限位于「角色与预算」。外部 HTTPS 始终验证证书；本机 HTTP 服务无需关闭 TLS 验证。高级兼容 JSON 只填写所选协议支持的非密钥选项。

## 4. 角色与预算

设置默认模型后，planner、verifier、reporter 可继承默认路由，也可分别选择其他已配置模型。

| 角色 | 用途 | 权限边界 |
| --- | --- | --- |
| planner：绑定 A | 独立读取语义、选择已登记维度与检索计划 | 不得提供事实金额或判定 |
| verifier：绑定 B | 使用独立会话再次绑定 | 不读取 A 的绑定历史 |
| reporter | 组织引用已冻结结果的文字 | 不得更改事实、公式或结论 |

A/B 使用同一个模型也保持独立会话，但这不意味着其统计误差完全独立。绑定不一致或定义未知时由内核保留阻断原因。

新配置默认任务预算为 30 分钟、128 次模型请求、1000 次工具调用、100 万 Token，追问默认 15 万 Token；已保存的自定义值保留原样。长研报建议结合材料量与账号价格提高预算，例如 60 分钟、512 次请求、4000 次工具、200 万 Token。增加预算只能解决额度阻断，不能补齐缺失的来源定义、报告或口径证据。

预算耗尽会显示 `partial` 和未处理条目。用量或价格无法获取时显示 `unknown`，不写成零。取消和恢复继续累计原任务预算，不能通过恢复增加额度。

## 5. 准备材料与路径

建议按任务建立独立目录，例如：

```text
D:\MingJingData\project-a\
  draft\research_report.pdf
  corpus\annual_2022.pdf
  corpus\annual_2023.pdf
  corpus\prospectus.pdf
  corpus\inquiry_reply.pdf
  knowledge\会计准则原文.pdf
  output\
```

研报草稿支持 PDF、Markdown 或文本；财报材料可选择单份 PDF 或目录。大型财报不会整体复制进 EXE。草稿在任务启动时复制并记录 SHA-256，财报保留外部引用并冻结实际输入哈希。

有 `index.csv` 时应补齐公司、期间、报告类型、披露日期、路径和哈希。披露日期未知的材料不能自动当作截止日前已经公开。年报、招股书、官方问询回复、更正公告应各保留原始身份；改名不能改变其披露版本。

期间示例：年度 `2023Y`，半年度 `2024H1`，单季度 `2024Q1`。全年、半年累计和单季不能混用。核查历史研报时「研报／分析截止日期」必须使用当时日期；本项目并行科技案例为 `2024-04-22`，不得用其后披露数据代替当时依据。

知识库在任务开始时建立只读索引并冻结。Agent 可以查原文，但来源、版本与有效日期需要独立核验；知识库文本不能直接替代签发规则生成金额或判定。

路径设置后点击「测试路径」或「校验配置」。默认拒绝符号链接、junction 和路径逃逸。若关闭「允许外部路径」，允许根必须覆盖材料、工作区、输出、临时、日志及应用登记/会话目录。选择目录不会自动扩大安全权限。临时目录应使用普通短路径，避免把 TEMP/TMP 设在多层长中文目录。

## 6. 运行研报纠错核查

1. 点击「新建金融任务」，选择「研报纠错核查」。
2. 选择草稿、财报材料，填写公司、期间、截止日期。
3. 选择「离线确定性内核」或「Harness 金融 Agent」。前者不调用模型，后者允许模型使用受控金融工具完成语义绑定与检索。
4. 研报口径默认「仅依据原文」。只有你确实能声明口径时才补充合并或母公司；声明作为条件核查材料归档，不能覆盖原文明确相反的口径。
5. 点击「开始任务」。任务页面显示实际阶段、角色和工具活动；进入历史查看同一任务不会重复创建任务。
6. 完成后逐条查看结论、来源、公式和建议。需要更多材料时按第 9 节建立补证版本。

模型只能选择登记资源与语义标识。事实值、公式和判定由金融内核执行。页面展示计划、动作与可审查依据，不把模型私有思考文本作为核查结论。

## 7. 运行财报分析

选择「财报分析」，草稿可以留空，选择财报 PDF 或目录，填写公司、期间、截止日期及合并/母公司口径。分析输出登记指标、操作数、证据、非经常性损益、会计变更/重述和利润现金流信号。

点击指标卡可查看实际规则、公式、量纲、操作数和原页来源。扣非重算所需四项缺失时不会默认零；EPS、ROE、净利率等定义存在分歧时展示具体方法阻断。分析中的提示阈值属于登记参数，不构成舞弊认定、交易指令或目标价。

## 8. 读懂结果、精度与覆盖

| 状态 | 意义 | 应采取的动作 |
| --- | --- | --- |
| 已核实 / `verified` | 在注明口径、时点、来源与披露精度下相容 | 查看验证依据与精度提示；条件核查另有标记 |
| 有误 / `violated` | 存在有来源依据的 E1–E7 或 E9 错误 | 查看正确值与五项修正，再复查修订稿 |
| 弃权 / `abstained` | 证据、绑定、方法或计算前提不足 | 按完整阻断链补充资料，不当作“无误”或“有错” |
| 待处理 / `pending` | 尚未执行完 | 检查预算、取消或异常，再恢复/新建任务 |
| 范围外 / 规则排除 | 预测、假设、行业、运营或有明确排除依据的内容 | 在分层账本中审查分类理由 |

E8 表示材料不可验证，对应弃权，不是已证实有错。X1–X6 分别对应可用事实缺失、公式/前提不足、绑定未知或分歧、解析/材料冲突、日期缺失和原文解析不足。A1–A5 是提示，不能代替三态。全部阻断原因应一起查看，解除第一个原因不保证其余原因消失。

结果统计按原文出现位置计算，并同时列出去重断言；两者不能混用。处理完成率包含已核实、有误和合法弃权，有效判定覆盖率只统计已核实与有误。条件核查与有原文支持的判定分开；来源支持覆盖率不把用户声明当成原文证据。弃权率、待处理数、公司历史财务与行业/运营/预测/假设各层分别展示。完成率 100% 不等于金融事实核实率 100%，也不等于人工金标测得的召回率。

「披露精度下相容」表示两侧 Decimal 区间存在相容关系，不表示细于披露精度的金额已独立核实。范围断言如「超过70%」按严格集合处理，不能改写为等于70%。

点击证据 ID 查看 PDF 原页与定位；原文件哈希发生变化时拒绝打开旧证据。五项修正包括正确值、来源/证据 ID、计算式、规则依据、可替换文本。建议值不应超出来源支持精度。

## 9. 追问、补证、澄清与重查

任务完成后点击「材料追问」或从历史选择会话。可以询问某个指标的来源、公式、变动、缺材或阻断原因。答案只引用关联任务中的冻结证据与内核槽位；知识库引用保留来源标签。

可使用三种补充方式：

1. 「补证后重查」追加财报材料或有依据的口径声明。
2. 证据面板「页面补证」重新读取该页与相邻页，最多三页，查看补证事实预览，再点击「创建补证版本」。没有新增信息或存在冲突的包会明确显示状态。
3. 「按表或指标补充口径」只声明选定分组，不影响其他组；声明不解除缺方法、缺日期或缺材料。

任何有效追加都创建新资源锁和新任务版本，原结果保持冻结。补证包在新版本重新验证；原材料或规则不兼容时要求重新补证，不静默丢弃。比较新旧版本时应同时检查增加了什么材料、声明了什么口径和哪些原文位置发生变化。

## 10. 取消、恢复、重放和导出

取消后可从历史恢复未冻结原生任务。恢复前检查材料、配置、插件、内核和运行时锁；旧版本不兼容时新建任务，不原地改写旧锁。冻结结果只读，重新核查建立新版本。

「内核重放」重新计算冻结事实、绑定与数字结果。「Agent 重放」使用缓存重新执行真实 Harness 工具循环；不联网兜底，缓存缺失或请求不匹配明确失败。冻结回答可点击「重放这条回答」，重新执行该消息的工具轨迹与引用。旧任务缺少当前所需缓存不代表能重建当时字节。

导出包含报告、结构化结果、账本、审计、工具轨迹、证据和登记的补证/消息引用；它不自动复制整个外部财报库，也不包含个人密钥。要给别人完整重放，另按 [DELIVERY_GUIDE.md](DELIVERY_GUIDE.md) 提供所需材料闭包。分享前核对材料再分发权限。

## 11. 本地数据与排障

```text
%LOCALAPPDATA%\MingJing\config.json         配置 v2 / revision
%LOCALAPPDATA%\MingJing\secrets.json        当前用户 DPAPI 密文
%LOCALAPPDATA%\MingJing\workspace\runs     默认任务输出
%LOCALAPPDATA%\MingJing\sessions           追问会话
%LOCALAPPDATA%\MingJing\runtime-cache      按哈希校验的运行时缓存
%LOCALAPPDATA%\MingJing\run_registry.json  跨输出目录历史登记
```

配置了自定义输出、临时或日志目录后，任务使用其冻结值。每个运行目录可查看 `run_manifest.json`、`audit.jsonl`、`session.jsonl`、`results.json` 和报告；日志使用脱敏内容。保留数量/天数字段当前是策略预留，不自动删除历史和父子依赖。

| 现象 | 检查顺序 |
| --- | --- |
| 页面未打开、重复启动仍是旧版 | 退出旧实例；检查自动浏览器设置、本地服务日志和版本 |
| 路径拒绝或中文文件无法读取 | 测试路径；确认实际文件存在、允许根、非junction；使用较短TEMP路径 |
| API 连接通过但 Agent 失败 | 检查工具闭环测试、具体模型、协议、请求路径、材料许可、超时和停止原因 |
| 大量弃权 | 先看完整阻断链及缺材清单；区分口径/方法/材料/解析；不要单纯提高Token |
| PDF capability false | 阶段EXE应内嵌PyMuPDF；源码检查锁定依赖，扫描件无可靠文本层不会被当作真值 |
| 原生运行时不可用 | 「运行时」检测已保存配置；检查缓存哈希与外部路径；可切换纯内核 |
| 重放失败 | 核对源材料、规则/插件锁和缓存是否齐全；不修改旧锁“修复”兼容性 |
| 换机密钥不可解密 | 在新Windows用户下重新输入API Token，导入不含密钥的配置后校验路径 |
| 更新设置冲突 | 刷新设置读取新revision再保存；运行中设置不会改变原任务 |

程序使用、GitHub协作、完整拷贝与轻量核心审阅的交付边界见 [DELIVERY_GUIDE.md](DELIVERY_GUIDE.md)。源码开发和构建见 [RUNBOOK.md](RUNBOOK.md) 与 [REBUILD_SOURCE.md](../scripts/REBUILD_SOURCE.md)。
