# 口径澄清材料

核查入口的 `scope_declaration` 接受严格枚举：空字符串、`合并`、`母公司`。默认空字符串表示仅按原文，不读取配置中历史的 `run.scope` 默认值，不把模型绑定或事实库中的口径当作原文证据。

用户明确选择口径后，宿主生成 `clarifications.json`，记载 `scope-clarification.v1`、`user_supplied_scope`、草稿 SHA-256 和稳定资源 ID。归档后文件 SHA-256 进入材料锁与清单，原子陈述只附引用元数据。原文、候选数值、字符定位、单位及其他口径维度保持原状。

明确原文口径优先。用户选择相反口径、原文同时声明两种口径，或所选口径被原文否定时，任务拒绝覆盖；应修订材料并创建新版本。归属于母公司股东的利润描述不是母公司报表口径证据。

CLI 使用 `--scope-declaration 合并` 或 `--scope-declaration 母公司`。Web 的 `/api/run`、`/api/runs/{id}/rerun` 和会话 `/materials` 接受同一枚举。只补充口径也会创建新任务版本；旧结果、原材料锁与会话保持不变。更换草稿时，若请求没有重新给出声明，就清除继承的旧澄清，以新原文为准。

JSON 的 `scope_declaration / clarifications`、Markdown 和 HTML 报告均披露用户补充来源、资源 ID 和哈希，不能称其为原文明示。测试中的澄清使用虚构材料与枚举，不代表用户已对真实开发研报作出声明；未声明的真实原文仍按缺少口径处理。
