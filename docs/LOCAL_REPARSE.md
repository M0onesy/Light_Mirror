# 局部原页补证与任务版本

局部补证实际读取锁定的原 PDF，最多读取登记页的前后各一页。它重新证明科目、公司、合并或母公司口径、单位、列期间和披露日期，并保留原文档完整 SHA-256、物理页、坐标及片段哈希。请求期间、模型候选金额和相近数值不能补足缺失的原文定义。无文本层、单位不明、缺少列头、未知披露日期或材料冲突不能生成可用金额。

## 原生 Agent 追检

协调器只有在 A/B 绑定一致、同一会话已查询事实且确实缺少该事实时，才能调用 `mj_request_reparse(block_id, binding_id)`。工具只接受登记的资源标识；绑定角色、金额、公式、判定和自由文件路径均不能作为输入。

活动任务使用 `staged` 提案：工具实际读取原页，但不更新活动事实库，不推翻已执行判定。模型摘要包含新增数量、页定位和证明哈希，不包含新金额或文件路径。工具循环可以继续处理其他陈述；当前缺证项仍按原事实库弃权。每个块最多追检两次，没有新信息则停止。

宿主先完成报告和审计、冻结所有提案文件，再重新验证原页，以完整父任务 generation 发布正式补证包。正式包保存于运行根的 `reparse/{run_id}`，不回写父任务。无法发布时，保留父判定并显示发布失败事件。`staged` 文件不能直接进入新任务。

## Web 操作

结果页“可用页面补证”列出 Agent 已发现的包，也支持原页证据面板手动重解析。可以预览新增事实、口径、期间、单位、披露版本与各项证据；页图片在内存渲染。随后点击“创建补证版本”，新任务在启动前加载通过源页重建的包并完整重新核查。原父任务、原材料及旧审计保持只读。

新任务的“补证材料”显示所有新增事实，包括未被本次陈述或分析指标引用的事实。此面板标为“原页补证事实”，它不生成独立研报 verified 判定。金额与单位使用宿主 Decimal 展示投影；未知标准单位明确显示未知。

一次新任务最多应用十二个同一冻结父任务的包。跨包、同披露版本的金额冲突进入 X4，整包禁止应用。相同金额但增加证据、同义扣非科目或同等级披露标签不能假称新增事实。

目前补证后的任务不能通过普通“重新核查”隐式继承多代包。界面会说明并要求从原父任务选择包新建版本；公司、草稿、材料、期间、口径或截止日改变时建立新的补证链。完全未登记的 PDF 需由用户明确追加材料，程序不会偷偷扫描其他文件扩大资源范围。

## 源码入口和重放

```powershell
python -m mingjing.cli check --draft path/to/draft.md --corpus path/to/corpus `
  --company 公司名 --period 2023Y --report-date 2024-04-22 --mode kernel `
  --reparse-parent-run runs/parent --reparse-packet path/to/rp-完整哈希.json `
  --out runs/new-version
```

CLI、Web 和原生 Agent 共用 `reparse_inputs.py` 加载入口。父清单、事实、陈述、输出、审计链、来源及补证包均重新验哈希；核查参数和初始事实基线必须一致。补证包在产生新材料锁之前加载，恢复时不得取得新的事实代次。

Kernel replay 从新任务冻结事实和绑定重新计算。Agent replay 从模型缓存执行真实 Harness 工具循环，原页追检仍由本地确定性工具重做；它不会获取在线凭据，不会联网兜底，也不会再次向原父目录发布包。请求或代码锁不一致时明确失败，旧运行锁不改写。
