# 冻结分析的可读槽位

财报分析继续返回内核的结构化 `analysis[].record`，数值、公式、操作数、阈值和证据不变。原来的 `analysis.<id>.<category>.<index>` JSON 槽位保留用于审计；新增同名 `.text` 槽位，由确定性中文展示程序生成。

`mj_analyze` 的默认 `slot_id / slot_ids / slots / slot_template` 引用 `.text`。`raw_slot_id` 只说明原冻结记录位置，不授权提交该原始槽位。会话必须实际读取可用槽位才能提交，不能通过猜测槽位 ID 或复用另一会话的权限绕过校验。

中文文本包含指标名、公司、期间、口径、标准值及单位、公式、操作数、原披露单位、事实与证据 ID、弃权原因。金额标准值使用元，每股收益使用元/股，比率以及 `_YOY / _QOQ` 指标显示精确百分比并保留无量纲标准值。显示转换不调用模型、不舍入内核值、不把缺项当零。

信号说明其财务复核用途，列出冻结阈值与登记来源；缺少阈值时不补写。会计变更及披露版本事件引用原记录和证据，不自行推断金额影响、投资结论或舞弊。动态源字符串按 Markdown 纯文本转义，不能成为外链、HTML 或新的模板槽位。

Dispatcher 的 `task_company` 仅由宿主传入。未指定时从唯一陈述主体或唯一事实主体推断，混合事实且没有可信主体时拒绝分析。事实、可用维度、报告元数据及关联报告块按任务公司隔离；原文中的可比公司数字保持源材料性质，不能作为当前公司的数字真值。

这些是源码功能与受控测试结果。没有使用模拟测试宣称真实供应商调用、金融金标评测或最终 Windows 发布验收通过。
